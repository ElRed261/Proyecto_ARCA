PASO A PASO: CREAR VPS EN ORACLE CLOUD
================================================================================

PASO 1: CREAR CUENTA ORACLE CLOUD
================================================================================

1. Ve a: https://www.oracle.com/cloud/free/

2. Clic en "Start for free"

3. Completa el registro:
   - Email válido
   - Nombre completo
   - País: Selecciona tu país
   - Home Region: IMPORTANTE - Elige una región con disponibilidad ARM
     Recomendadas: 
       * US East (Ashburn)
       * Germany Central (Frankfurt)
       * UK South (London)
       * Brazil East (Sao Paulo) ← Si estás en Latinoamérica
   
4. Verificación de identidad:
   - Número de teléfono
   - Tarjeta de crédito (NO TE COBRAN, solo verifican)
   
5. Espera confirmación por email (puede tardar 1-24 horas)

NOTA: Oracle NO cobra si usas recursos "Always Free". La tarjeta es solo 
para verificar que eres persona real.


PASO 2: CREAR INSTANCIA VM (VPS)
================================================================================

1. Inicia sesión en: https://cloud.oracle.com

2. Menú hamburguesa (☰) → Compute → Instances

3. Clic en "Create Instance"

4. Configurar:

   a) Name: ARCA-Server
   
   b) Placement: 
      - Availability Domain: AD-1 (o el disponible)
   
   c) Image and Shape:
      - Clic en "Edit" → "Change Shape"
      - Selecciona: "Ampere" (arquitectura ARM)
      - Shape: VM.Standard.A1.Flex
      - OCPUs: 4 (máximo gratis)
      - Memory: 24 GB (máximo gratis)
      - SO: Ubuntu 22.04 (Canonical)
   
   d) Networking:
      - VCN: Crear nueva o usar existente
      - Subnet: Public Subnet
      - Marcar: "Assign a public IPv4 address"
   
   e) SSH Keys:
      - Opción A: "Generate a key pair for me" (descarga las keys!)
      - Opción B: "Paste public keys" (si ya tienes SSH key)
      
   f) Boot Volume:
      - Size: 100 GB (o hasta 200 GB)
      - Encryption: Por defecto

5. Clic en "Create"

6. Espera 2-5 minutos hasta que el estado sea "RUNNING"

7. Anota la IP pública (ej: 129.151.xxx.xxx)

POSIBLE ERROR: "Out of host capacity"
Si aparece este error, significa que no hay capacidad ARM en esa región.
Soluciones:
- Intenta en otra Availability Domain (AD-2, AD-3)
- Intenta en horario de baja demanda (madrugada UTC)
- Prueba otra región
- Usa scripts de reintento automático (buscar "OCI ARM retry script")


PASO 3: ABRIR PUERTOS EN EL FIREWALL DE ORACLE
================================================================================

Por defecto, Oracle bloquea todo excepto SSH (22).
Necesitas abrir: 80 (HTTP), 443 (HTTPS), 8000 (FastAPI)

1. Menú (☰) → Networking → Virtual Cloud Networks

2. Clic en tu VCN

3. Clic en el Subnet público

4. Clic en la Security List (ej: "Default Security List...")

5. "Add Ingress Rules":

   Regla 1 - HTTP:
   - Source CIDR: 0.0.0.0/0
   - IP Protocol: TCP
   - Destination Port: 80
   
   Regla 2 - HTTPS:
   - Source CIDR: 0.0.0.0/0
   - IP Protocol: TCP
   - Destination Port: 443

   Regla 3 - FastAPI:
   - Source CIDR: 0.0.0.0/0
   - IP Protocol: TCP
   - Destination Port: 8000

6. Guardar cambios

PASO 6: CONFIGURAR FIREWALL DE UBUNTU (iptables)
================================================================================

Oracle tiene su propio firewall, pero Ubuntu también tiene iptables.
Necesitas abrir los puertos en ambos:

sudo iptables -I INPUT 6 -m state --state NEW -p tcp --dport 80 -j ACCEPT
sudo iptables -I INPUT 6 -m state --state NEW -p tcp --dport 443 -j ACCEPT
sudo iptables -I INPUT 6 -m state --state NEW -p tcp --dport 8000 -j ACCEPT

# Guardar reglas permanentemente
sudo netfilter-persistent save


PASO 7: CONFIGURAR NGINX COMO PROXY INVERSO
================================================================================

sudo nano /etc/nginx/sites-available/arca

# Contenido:
server {
    listen 80;
    server_name TU_IP_PUBLICA;  # O tu dominio si tienes

    location / {
        proxy_pass http://127.0.0.1:8000;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection 'upgrade';
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_cache_bypass $http_upgrade;
    }
}

# Activar configuración
sudo ln -s /etc/nginx/sites-available/arca /etc/nginx/sites-enabled/
sudo nginx -t
sudo systemctl restart nginx

CAMBIO 4: SCRIPT DE SINCRONIZACIÓN EN ESTACIÓN LOCAL
================================================================================

Archivo: sync_to_server.py (nuevo, en raíz de Proyecto_ARCA)

#!/usr/bin/env python3
"""
Script para sincronizar observaciones locales al servidor central.
Ejecutar manualmente o via cron cuando hay internet.
"""
import os
import json
import requests
from pathlib import Path

SERVER_URL = "http://TU_IP_PUBLICA:8000/api/synoptic/sync"
TOKEN = "TU_TOKEN_JWT"  # O usar login primero
DATA_DIR = Path("backend/app/modules/synoptic/data")

def sync_pending():
    """Sincroniza todos los JSON no sincronizados."""
    headers = {"Authorization": f"Bearer {TOKEN}"}
    
    for json_file in DATA_DIR.rglob("*.json"):
        # Leer JSON local
        with open(json_file, "r") as f:
            data = json.load(f)
        
        # Extraer info
        station_code = data["meta"]["estacion"]
        fecha = data["meta"]["fecha"]
        
        # Enviar al servidor
        try:
            response = requests.post(SERVER_URL, json={
                "station_code": station_code,
                "fecha": fecha,
                "json_data": data
            }, headers=headers, timeout=30)
            
            if response.status_code == 200:
                print(f"✓ Sincronizado: {json_file.name}")
            else:
                print(f"✗ Error {response.status_code}: {json_file.name}")
        except requests.exceptions.RequestException as e:
            print(f"✗ Sin conexión: {e}")
            break

if __name__ == "__main__":
    sync_pending()
